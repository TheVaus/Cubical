# Triage

Ripen an issue until an agent or a human can pick it up cold. Cubical's tracker
is a *record*, not a queue: the filing discipline is already good and the gap is
that nothing turns a filed idea into something takeable. That is this skill.

The tracker, the label vocabulary and the milestone rule are owned by
[`sessions.md`](../../../docs/principles/sessions.md). Read it before applying a
label. If the labels below do not exist, run `/setup-matt-pocock-skills`.

Every comment posted during triage starts with:

```
> *This was generated by AI during triage.*
```

## Reference

- [AGENT-BRIEF.md](AGENT-BRIEF.md): what a `ready-for-agent` brief must carry.

## Roles

Two **category** roles, both existing labels: `bug`, `enhancement`. An `idea` is
not a category — it is the scheduling statement, and it stays on the issue.

Four **state** roles plus one absence:

| State | Means |
|---|---|
| *(no state label)* | Never triaged. The resting state of most of the tracker, and not a defect. |
| `needs-triage` | Triage **started** and stopped mid-way. Partial notes are on the issue. |
| `needs-info` | Blocked on an answer only the operator can give. |
| `ready-for-agent` | A brief is attached; an AFK agent can take it cold. |
| `ready-for-human` | Specified, but needs judgement, an interactive smoke, or credentials an agent does not have. |
| `wontfix` | Closed, with the reason recorded. |

A triaged issue carries exactly one category and one state. Conflicting state
labels are a bug in the tracker: flag it and ask before doing anything else.

Transitions: absent → `needs-triage` → one of `needs-info` / `ready-for-agent` /
`ready-for-human` / `wontfix`. `needs-info` returns to `needs-triage` once the
operator answers. Flag anything unusual and ask.

## Never sweep

**Absence of a state label is the record, not a backlog awaiting grooming.** An
issue with no milestone and no state label is exactly what
[`sessions.md`](../../../docs/principles/sessions.md) intends: *what*, never
*when*. Nothing here closes, relabels or chases an issue for age. Triage runs
only on issues the operator names, or on the shortlist it offers when asked —
and the offer is a shortlist, never the whole tracker.

The one report worth volunteering: an issue whose `blocked` label outlived its
`Blocked by #N` (the blocker closed). That is a stale fact, not a stale issue.

## Invocation

The operator invokes `/triage` and describes what they want. Interpret and act:

- "What needs my attention?" → the three buckets below.
- "Let's look at #204" → work it up.
- "Move #217 to ready-for-agent" → quick override.
- "What can an agent pick up?" → `gh issue list --label ready-for-agent`.

## Show what needs attention

Three buckets, oldest first, counts and a one-line summary each. Cap each bucket
at ten and say what you truncated — a full dump of the tracker is not triage.

1. **`needs-triage`** — started, unfinished. Always the first bucket.
2. **`needs-info` with operator activity since the last triage note.**
3. **Unlabelled, and *scoped by the area the operator named*.** Never the whole
   tracker. With no area given, ask for one rather than listing everything.

Then let the operator pick.

## Triage one issue

1. **Gather context.** Read the issue whole — body, comments, labels, dates.
   Parse prior triage notes so you do not re-ask a settled question. Delegate
   the codebase sweep to an `explorer` ([`subagents.md`](../../../docs/principles/subagents.md)),
   and read the area's [`docs/implementation/`](../../../docs/implementation/)
   file and whatever [`docs/architecture/`](../../../docs/architecture/) locks.
   Two checks: **(a) redundancy** — search by capability, not by the issue's
   wording, and say where you looked; **(b) prior rejection** — read
   [`docs/architecture/constraints.md`](../../../docs/architecture/constraints.md),
   which owns what has been cut, and surface anything that resembles this.
   An explorer's report is a claim: verify anything load-bearing yourself.

2. **Recommend.** Category, state, and why, plus what the codebase already does
   here. Wait for direction.

3. **Verify the claim.** For a bug, reproduce it — a failing test or a command
   with its output, not an argument that it must fail. For a perf claim, the bar
   and the measurement live in [`foundation.md`](../../../docs/architecture/foundation.md);
   an unmeasured perf claim is `needs-info`, never `ready-for-agent`. Report
   confirmed (with the code path), failed, or insufficient detail. A confirmed
   reproduction is the difference between a brief and a guess.

4. **Grill, if it needs shape.** Call the Skill tool for `grilling`. Decisions
   that land against a locked doc are edited into that doc's owner as they land,
   never restated on the issue.

5. **Apply the outcome.**
   - `ready-for-agent` → post the brief ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human` → the same brief, plus the sentence saying what stops an
     agent: a design call, an interactive `cargo tauri dev` smoke, signing
     material, or anything reaching outside the repo.
   - `needs-info` → post the notes template below.
   - `wontfix` → close, and record why:
     - **Already built**: point at where it lives. Nothing else to write.
     - **Rejected**: the rejection is a scope fact, so it belongs to
       [`constraints.md`](../../../docs/architecture/constraints.md). Add it
       there in the same session, link the issue to it, then close. Do **not**
       start an `.out-of-scope/` tree; that fact already has an owner.
   - `needs-triage` → apply the label and leave the partial notes.

Applying a state label is not a commit. If step 4 or 5 edited a doc, that change
is committed and pushed like any other — [`sessions.md`](../../../docs/principles/sessions.md)
binds this session, not a future one.

## Quick override

"Move #42 to ready-for-agent" — trust it. Confirm what you are about to do
(labels, comment, close), then do it. Skip grilling. If it is going to
`ready-for-agent` without a brief, ask whether to write one; a `ready-for-agent`
label with no brief is a promise the next agent cannot collect on.

## Needs-info template

```markdown
> *This was generated by AI during triage.*

## Triage notes

**Established so far:**

- point

**Still needed:**

- specific, answerable question
```

Everything settled during grilling goes under "established" so the work is not
lost. Questions are specific and answerable, never "please provide more info".

## Resuming

If triage notes already exist, read them, check what has been answered since,
and present the updated picture before continuing.

## Local edits

Cubical substitutions for upstream's generic tracker: the five canonical states
became four-plus-absence so an untriaged issue stays a record rather than a
queue entry; the `.out-of-scope/` knowledge base became
`docs/architecture/constraints.md`, which already owns that fact; `CONTEXT.md`
and ADRs became `docs/architecture/` and `docs/implementation/`; the
`domain-modeling` skill call was dropped, as it is not installed and imports a
conflicting doc regime; codebase sweeps go to the `explorer` agent; discovery is
scoped and capped rather than tracker-wide; and PRs are not a request surface
here. Preserve these when re-syncing against upstream.
