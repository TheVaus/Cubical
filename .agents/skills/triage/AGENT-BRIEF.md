# Writing agent briefs

A brief is the comment posted when an issue moves to `ready-for-agent`. The
issue body and its discussion are context; **the brief is the contract**, and it
is what a cold agent will build from days or weeks later.

The `feature` template already asks for Why · Design · Task graph · Acceptance
criteria. When the issue was filed on that template and is still accurate, the
brief says so and fills only the gaps — do not restate a section that is already
right, for the same reason [`single-owner-facts`](../../../docs/principles/single-owner-facts.md)
gives. A brief that duplicates the body is a second copy to keep in sync.

## What makes a brief durable

**Anchor on symbols, not paths.** A path goes stale; a `#[tauri::command]` name,
a Rust type, a table name or an exported TS symbol survives the move. This is
the same reason [`implementation-anchors`](../../../docs/principles/implementation-anchors.md)
exists, and the anchors it already enforces are the vocabulary to reuse.

**Name the crate, though.** [`crate-separation`](../../../docs/principles/crate-separation.md)
decides where a change is allowed to live, and an agent that guesses wrong
writes code the dependency-boundary gate rejects. "In `cubical-index`, behind the
existing query surface" is durable; `crates/cubical-index/src/query.rs:88` is not.

**Behavioural, not procedural.** Say what the system must do. The agent explores
fresh and makes its own implementation calls.

**Acceptance criteria a verifier can check.** Each one independently verifiable,
against the issue rather than against the author's intent — that is what the
`verifier` agent is pointed at ([`subagents.md`](../../../docs/principles/subagents.md)).
"Renaming a note leaves no stale referrer link" is checkable. "Renames work
properly" is not.

**Say which gates it must clear.** `scripts/check.sh` is the whole set, but name
the one this change is most likely to trip — a new component and its size budget,
a doc that needs an ownership row, a generated artifact that must be regenerated,
a perf-sensitive path and its budget. An agent that learns about the gate from a
red run has already built the wrong shape.

**Say whether it needs a smoke.** Anything touching a rendered or interactive
surface needs an interactive `cargo tauri dev` pass, which an AFK agent cannot
do. If it does, the issue is `ready-for-human`, not `ready-for-agent` — or the
brief names the smoke as the operator's step and scopes the agent to the rest.

## Template

```markdown
> *This was generated by AI during triage.*

## Agent brief

**Category:** bug / enhancement
**Crate / surface:** where this is allowed to live
**Summary:** one line

**Current behaviour:**
What happens now, and how it was confirmed — the reproduction, the failing
command, or the measurement. Not an argument that it must be broken.

**Desired behaviour:**
What should happen, including the edge cases and the failure mode.

**Anchors:**
- `SymbolName`: what changes about it and why
- the wire type or table this crosses, if it crosses one

**Acceptance criteria:**
- [ ] independently verifiable
- [ ] independently verifiable

**Gates it must clear:** the ones beyond a plain green `scripts/check.sh`
**Smoke:** none / interactive `cargo tauri dev` on <surface>

**Out of scope:**
- the adjacent thing that will look related and is not
```

## Worked example

```markdown
> *This was generated by AI during triage.*

## Agent brief

**Category:** bug
**Crate / surface:** `cubical-index`; no UI change
**Summary:** A cancelled or failed scan leaves the index partial and offers no
way to re-run it

**Current behaviour:**
Confirmed: interrupting a scan of a vault mid-run leaves the index holding the
files scanned so far, with nothing recording that the scan did not finish. A
subsequent open treats the partial index as complete, so a search silently
misses every unscanned note. No surface re-runs the scan.

**Desired behaviour:**
A scan that does not run to completion leaves the index marked incomplete, and
an incomplete index is rebuilt on next open rather than trusted. Cancellation
and failure take the same path: an index is either complete or rebuildable, per
[`derived-state-disposable`](../../../docs/principles/derived-state-disposable.md).

**Anchors:**
- the scan entry point and whatever currently signals its completion
- the schema row or file recording index state, if one exists; if not, this
  brief is asking for one

**Acceptance criteria:**
- [ ] A scan interrupted part-way leaves the index marked incomplete
- [ ] Opening a vault whose index is incomplete rebuilds it before serving a query
- [ ] A scan that fails with an error takes the same path as a cancellation
- [ ] A test drives an interrupted scan and asserts the rebuild

**Gates it must clear:** `cargo test --workspace`; the perf gate if the rebuild
lands on the vault-open path
**Smoke:** none — headless, backend only

**Out of scope:**
- Resuming a partial scan rather than rebuilding it. Rebuild is correct here;
  resumption is a separate optimisation and needs its own measurement.
- Any surfacing of scan state in the UI
```

## What a bad brief looks like

A summary of "fix the index bug", a list of file paths with line numbers, no
reproduction, no acceptance criteria, and no scope boundary. Every one of those
is a decision the cold agent now has to invent, and it will invent a different
one than you would have.
