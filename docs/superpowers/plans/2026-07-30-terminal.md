## The IPC contract (fixed — B1 and B2 both build to this)

Tauri commands:

| Command | Args | Returns |
|---|---|---|
| `terminal_open` | `vault_id`, `cols`, `rows`, `on_output: Channel<TerminalChunk>` | `{ terminal_id: String }` |
| `terminal_write` | `terminal_id`, `data: String` | `()` |
| `terminal_resize` | `terminal_id`, `cols`, `rows` | `()` |
| `terminal_close` | `terminal_id` | `()` |

Output streams over a Tauri **`ipc::Channel`** handed in at open — one channel per terminal, not a global event. `TerminalChunk` is `{ base64: String }`.

**Bytes, not strings.** A PTY emits raw bytes and a multi-byte UTF-8 character can split across chunk boundaries; decoding per-chunk corrupts it. The backend base64-encodes raw bytes, the frontend decodes to `Uint8Array` and hands that to xterm.js `write()`, which handles continuation itself. Do not `String::from_utf8_lossy` on the backend.

Exit is signalled by the channel closing, plus a final chunk the frontend renders as a dim exit notice.

## B1 — Rust PTY backend

New `crates/cubical-app/src/terminal.rs`, mirroring how `console.rs` is isolated (one `mod` + a handful of registered commands in `lib.rs`).

- `portable-pty` for the PTY pair and child spawn. Shell from `$SHELL`, fallback `/bin/sh`.
- Child env: cwd = vault root; `CUBICAL_VAULT` = vault root; app binary dir prepended to `PATH` so `cubical` resolves.
- A session registry (id → handle) in app state. Reader task per terminal pumping bytes into the channel.
- **Reaping is the risk.** `terminal_close`, vault switch, plugin disable, and app exit must all reap: `SIGTERM`, then `SIGKILL` after a grace period. A hidden `claude` mutating the vault with no visible tab is the exact failure this must not have.
- No confinement — unrestricted is the explicit ask (`foundation.md` §2.1 conditions are what replace the sandbox).

## B2 — xterm.js frontend

New `ui/src/terminal/`, mirroring `ui/src/console/`'s layout.

**Adapter boundary is mandatory** (spec §Emulator): nothing outside `ui/src/terminal/` may import xterm.js. The adapter exposes only write-bytes / resize / focus / dispose / key-handler.

**Theme shim:** xterm.js is configured from a theme object derived from DS tokens at mount and re-derived on theme change; its stylesheet is scoped to the terminal container. xterm.js contributes no colour of its own.

Add `@xterm/xterm` + `@xterm/addon-fit` to `ui/`. Wire resize → `terminal_resize` so the PTY's winsize matches, or full-screen TUIs render wrong.

## B3 — Tab kind, wiring, plugin gate

- `{kind:"terminal"}` added to the `TabView` union. **Not a singleton** — multiple terminals.
- Excluded from the keep-alive LRU (`liveFileIds`) and from session persistence. T6 already flipped `isPersistableTab` to allowlist `file`/`tag`, so persistence exclusion should be automatic — **verify, don't assume**.
- Closing a tab with a live foreground child confirms first.
- Core plugin `plugins.terminal_enabled`, **default off**, registered like `CONSOLE_PLUGIN`. Disabling closes all terminal tabs and reaps children.
- The console stays. It is removed in a **separate later commit**, once the terminal is proven.
