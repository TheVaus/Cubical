## The task: L4-D — Dataview-style libSQL queries

Typed-frontmatter projection that complements Tantivy full-text: where
search answers "which notes match these words?", this answers "list
every project with `status: in-progress` sorted by `due_date`." See
`docs/layer-4-spec.md` §1.6, §2 (Session D), §3.2, §6.

**Shape (from the spec, to be refined in brainstorming):**
- A query **AST + parser** for `list` / `table` / `count` over typed
  frontmatter, filtered by tag, path, and scalar comparisons.
- **Execution** over libSQL — the substrate already exists:
  `frontmatter(file_path, key, value)` (value is JSON-encoded; table
  built since L1, see `crates/cubical-index/migrations/002_frontmatter.sql`),
  plus `tags`, `links`, `files`.
- A **renderer** for query blocks embedded in `.md` source (e.g. a
  fenced ```` ```dataview ```` block) — detect, evaluate, render the
  result table/list/count in the editor.

**Decisions to make in brainstorming (don't assume):**
1. New `cubical-query` crate vs. extending `cubical-index`.
2. Query syntax — a small custom DSL vs. an Obsidian-Dataview subset.
   YAGNI hard; pick the smallest grammar that does list/table/count +
   `WHERE` on tag/path/frontmatter scalars + `SORT`.
3. Block detection + render path in the editor (how the canonical AST
   surfaces a query block; live re-eval on vault content change — there's
   already `searchRefreshTick` for that signal).
4. New IPC command(s) for query execution (keyed on libSQL side).
5. Scope: which value types/comparisons for v1; date-range + multi-term
   fuzzy are explicitly *optional* (L4-A non-goals the spec says L4-D
   *may* layer on — defer unless trivial).

## Process (per the repo's skills)

1. **Brainstorm first** (superpowers:brainstorming) — explore, decide the
   five points above, get sign-off. **No code before an approved design.**
2. Write the spec to `docs/superpowers/specs/YYYY-MM-DD-l4-d-*.md`; commit.
3. superpowers:writing-plans → a TDD plan in `docs/superpowers/plans/`.
4. Implement TDD on a `feat/l4d-*` branch (single checkout + branches;
   **no worktrees**). UI components are operator-smoke-only (Contract E);
   put logic in pure, unit-tested modules.
5. Six gates green (`cargo test`/`clippy`/`fmt`, `tsc`, `vitest`,
   `build`), operator smoke, merge to `main`, tag `l4d`.
